# تشغيل الـ Autopilot: بناء المشروع كاملًا بشكل مستقل

البرومبت الكامل في `prompts/AUTOPILOT.md`. الملف ده بيشرح إزاي تشغّله، وإزاي تتابعه، وإزاي تتدخل لو احتجت.

## الفكرة في سطرين
كل دورة تبني **شريحة واحدة كاملة** في جلسة Claude Code جديدة بسياق نظيف: فرع، ثم Commit لكل خطوة، ثم مراجعة، ثم تسجيل، ثم دمج.
الحالة محفوظة في git وفي `.autopilot/state.json`، فأي جلسة تعرف تكمّل من مكان اللي قبلها.

```
scripts/autopilot.sh
  └─ loop: claude -p "$(cat prompts/AUTOPILOT.md)"   ← دورة = شريحة
        ├─ يقرأ state.json ثم يختار الشريحة التالية
        ├─ feat/SXX-… ← spec ← tests(xfail) ← feat × n ← review ← docs
        ├─ يسجل في BUILD_LOG.md وDECISIONS.md وPROGRESS.md
        └─ merge إلى main ← tag ← يحدّث state.json ← exit
  └─ يقف عند: done | blocked | 3 دورات بلا تقدم | MAX_ITER
```

## 1. قبل التشغيل (مرة واحدة)
```bash
unzip transcribe-engine-starter.zip && cd transcribe-engine
git init -b main && git add -A && git commit -m "chore(repo): add starter repo"
make setup && make up && make check      # لازم ينجح قبل أي حاجة
claude --version                         # حدّث Claude Code لآخر إصدار
```
- **Docker لازم يكون شغّال.** الاختبارات التكاملية وPostgres وMinIO كلها عليه.
- اختياري: `gh auth login` وريبو على GitHub. لو موجودين، الـ Agent يفتح PR لكل شريحة ويدمجه بعد نجاح CI. لو مش موجودين، يعمل كل حاجة محليًا بـ fast-forward merge.
- املأ أي إعدادات تخصك في `.env` بنفسك. الـ Agent ممنوع يقرأ الملف ده.

## 2. التشغيل

### الطريقة الموصى بها: الحلقة الآلية
```bash
make autopilot                         # أو: scripts/autopilot.sh
MAX_ITER=3 scripts/autopilot.sh        # جرّب 3 شرائح الأول وراجع النتيجة
BUDGET_PER_RUN=15 scripts/autopilot.sh # حد أقصى للتكلفة لكل دورة (بالدولار)
```
- كل دورة جلسة `claude -p` جديدة، فالسياق مايتراكمش ومايتلخبطش بين الشرائح.
- وضع الصلاحيات الافتراضي هو **`auto`**: نموذج تصنيف يراجع الأفعال في الخلفية، فمش هتحتاج توافق على كل أمر. والسكريبت بيضيف `--permission-prompts none` لو إصدارك بيدعمه. الخيار ده بيخلي أي أمر كان هيحتاج سؤالًا يُرفض بدل ما يستنى، فالحلقة ماتقفش مستنية رد.
- **لا تستخدم `bypassPermissions`.** التوثيق بيقول إنه للبيئات المعزولة فقط، زي الحاويات أو الأجهزة الافتراضية من غير إنترنت. السكريبت بيرفضه أصلًا.
- لو وضع `auto` مش متاح في حسابك: `MODE=acceptEdits scripts/autopilot.sh`. الأوامر المسموحة في `.claude/settings.json` هتشتغل، وأي أمر تاني هيترفض ويتسجل.

### الطريقة البديلة: جلسة تفاعلية واحدة
افتح `claude` في المجلد واكتب:
```text
Follow @prompts/AUTOPILOT.md. Run iterations continuously until the build is done or blocked.
```
مناسبة لو عايز تتفرج وهو شغّال. عيبها إن السياق بيكبر، والملخص التلقائي للسياق قد يضيّع تفاصيل. البرومبت بيطلب منه يرجع يقرأ ملفات الحالة بعد كل تلخيص، لكن الحلقة الآلية أنظف.

## 3. المتابعة

| عايز تعرف | افتح |
|---|---|
| وصل لفين؟ | `docs/PROGRESS.md` أو `jq .status,.current .autopilot/state.json` |
| بنى إيه وإزاي، بالتفصيل | `docs/BUILD_LOG.md` (قسم لكل شريحة: الخطوات والـ Commits والمشاكل والحلول) |
| أخد أنهي قرارات ولماذا | `docs/DECISIONS.md` (D-001، D-002، …) و`docs/adr/` |
| محتاج منك إيه | `docs/REVIEW_QUEUE.md` |
| جهازك والـ Profile اللي اختاره | `docs/LOCAL_ENV.md` |
| سجل الدورات والتكلفة | `.autopilot/logs/runs.tsv` |
| تاريخ الشغل | `git log --oneline --graph` و`git tag` |

## 4. نقاط تتدخل فيها (مش لازم، لكن مفيدة)
1. **بعد `v0.1.0` (S01):** راجع إن الأساس سليم على جهازك.
2. **بعد قرار D-001 (الـ Profile المحلي):** هل اختيار محرك الـ ASR المحلي مناسب لجهازك؟
3. **بعد `v0.3.0-local`:** جرّب `make demo FILE=…` على ملف حقيقي بنفسك، وافتح الـ SRT في مشغل.
4. **أي وقت:** راجع `REVIEW_QUEUE.md`. أهم بند هو **R-001**: ساعة صوت مصري مفرغة يدويًا. من غيرها الدقة المطلقة مش مقاسة، والمحرك الافتراضي قرار مؤقت.

## 5. إزاي تتدخل
- **توقف مؤقت:** `Ctrl+C`. الشغل محفوظ في commits، والدورة الجاية بتكمّل من آخر خطوة سليمة.
- **تغيير قرار أو إجابة بند:** اكتب في `docs/REVIEW_QUEUE.md` تحت *Instructions for the next run*. مثال:
  `R-001 done: data in data/eval/; finish S00 and revisit D-001`
  أو: `Supersede D-014: use pyannote, not Sortformer`.
  الدورة الجاية تنفذ التعليمات الأول، وتسجل قرارًا جديدًا يحل محل القديم.
- **فك حالة `blocked`:** حل السبب المكتوب، وارجع الشريحة لـ `todo` في `state.json`
  (`jq '.status="running" | .slices.S13.status="todo"' …`)، وبعدين شغّل السكريبت تاني.
- **إعادة شريحة:** احذف فرعها، وارجعها لـ `todo`. الـ commits اللي اتدمجت في `main` تفضل زي ما هي. التراجع عنها بيكون بـ `revert` في فرع `fix/`.

## 6. الضمانات اللي بتخليه آمن وهو شغّال لوحده
- **الـ Hooks:**
  - لا commit على `main`، ولا force push، ولا `--no-verify`.
  - `make check` إلزامي قبل ما ينهي أي مهمة.
  - التنسيق تلقائي بعد كل تعديل.
- **قواعد البرومبت:**
  - ممنوع يعدّل اختبارات قائمة عشان تنجح، أو يخفض حدود التغطية، أو يقرأ `.env`، أو يلمس ملفات خارج الريبو، أو يستخدم `sudo`.
  - القرارات اللي فيها فلوس أو حسابات أو مفاتيح أو تراخيص أو مسائل قانونية **مايقررهاش لوحده**. بيسجلها في REVIEW_QUEUE، ويحط بديل مؤقت (Fake أو Stub)، ويكمل.
- **كل قرار مسجل بالبدائل وسببه ودرجة الثقة فيه.** القرارات صعبة التراجع ليها ADR كمان.

## 7. أولوية التشغيل المحلي
- **أول Bootstrap:** يكتشف جهازك (نظام التشغيل، الرامات، كارت الشاشة، Docker) ويختار **Profile** محلي، ويسجله كـ D-001:
  - NVIDIA بـ 16 جيجا VRAM أو أكثر ← vLLM محليًا، زي الإنتاج.
  - Mac Apple Silicon ← محرك أصلي على Metal للتطوير بس، والإنتاج يفضل vLLM.
  - CPU فقط ← نموذج صغير للتجارب، والـ Fake للاختبارات.
- **ترتيب الشرائح معدّل:** S15 اتقدمت عن S13 وS14 عشان يوصل بسرعة لـ **`v0.3.0-local`**. عند النقطة دي:
  - `make dev` يشغّل كل المنصة على جهازك.
  - `make demo FILE=audio.mp3` يطلّع JSON وSRT وVTT في `out/`.
- **ولا اختبار يحتاج خدمة سحابية.** النشر على السحابة خارج النطاق، وبيظهر كتوصية في `docs/FINAL_REPORT.md` في الآخر.
